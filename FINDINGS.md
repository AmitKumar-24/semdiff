| F-009 | T-17 | Full normalization (parse + all five families) takes 54–520 ms on the five T-04 captures (docs.python.org 110 KB: 519 ms, 978 whitespace applications) — 1.5–5× over the NFR-3 sub-100 ms target for the parse+normalize path. Likely cost: `Locator.for_node` builds a positional CSS path per application (a parent walk with sibling counting). Profile before T-19/T-21 and consider lazy or cheaper locators; not a T-17 correctness issue. |
| F-010 | T-19 | `canonical.whitespace` collapses **non-ASCII** whitespace: its `_WS` pattern is `\s+`, which is Unicode-aware in Python, so U+00A0 (`&nbsp;`), U+2009 and friends count as collapsible layout. The HTML spec collapses only ASCII whitespace; `&nbsp;` is content. Consequence: `normalize("<p>a&nbsp;b</p>") == normalize("<p>a b</p>")`, so a real nbsp/space edit is invisible to the diff. **Resolved in the T-19 change set (D-035):** `_WS` is now `[\t\n\f\r ]+` and `canonical.whitespace` is at `version = 2`. |
| F-011 | T-19 | `semdiff.normalize` (the function) shadows the `semdiff.normalize` **subpackage** attribute, exactly as `semdiff.parse` already shadows `semdiff/parse.py`. `from semdiff.normalize import X`, `importlib.import_module` and deep submodule imports all still work, but `import semdiff.normalize as x` binds the *function*, and pytest's string-target `monkeypatch.setattr("semdiff.normalize.registry....")` no longer resolves (two tests now pass the module object instead). Pre-existing pattern, required by FR-10 + D-030; the alternative is renaming the subpackage to `semdiff._normalize`. |
| F-012 | T-19 | Performance baseline for F-009, measured through the public API on the five T-04 captures (best of 5, 3.12): 122 / 171 / 203 / 282 / 550 ms total, of which parse is only 2.5–11.9 ms. **>95% of the cost is the rule engine**, not parsing — so F-009's suspicion (`Locator.for_node` per application, 249–1652 applications per page) is where to look. Still 1.2–5.5x over NFR-3. |
